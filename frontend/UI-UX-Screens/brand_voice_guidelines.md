# Skillaude Brand Voice Guidelines

**Platform Name:** Skillaude  
**Tagline:** Build Skills That Think With You

## 1. Purpose

This document defines how Skillaude should sound in product copy, marketing copy, onboarding, interface text, documentation, and launch materials.

The goal is consistency.

Skillaude should sound like a serious builder product:
clear, calm, structured, useful, and exact.

## 2. Core Voice Principle

Write as if you are helping a capable builder move through a structured workflow with confidence.

The voice should never sound distracted, theatrical, inflated, or vague.

## 3. Voice Attributes

Skillaude’s voice should be:

- calm
- precise
- instructive
- composed
- practical
- technically credible
- concise
- quietly confident

It may also feel:

- premium
- thoughtful
- mature
- well-organized

## 4. Voice Attributes to Avoid

Do not sound:

- loud
- playful in a gimmicky way
- overexcited
- mystical
- futuristic by cliché
- salesy
- bloated
- breathless
- self-congratulatory
- vague

Avoid the tone of consumer AI hype.

## 5. Writing Model

The writing model should follow this order:

1. clarify what the user is seeing or doing
2. explain the next step
3. reduce ambiguity
4. create confidence
5. keep momentum moving

Do not add decorative language before the meaning is clear.

## 6. Tone by Context

### Product UI
Use short, clear, low-friction language.

Examples:
- Create from GitHub
- Upload Folder
- Resume Draft
- Validation Complete
- Missing Required Metadata

### Onboarding
Use calm, explanatory language that reduces hesitation.

Examples:
- Start from a repo, a local folder, or a blank skill.
- Choose the path that matches what you already have.
- You can resume this setup later.

### Documentation
Be structured, explicit, and directive.

Examples:
- Add a name, description, and usage instructions.
- Review detected files before generating the skill package.
- Export only after validation passes.

### Marketing
Stay restrained. Lead with utility, not spectacle.

Examples:
- Build and test AI skills in one workspace.
- Turn repos and folders into structured skill packages.
- Keep drafts, scans, and handoffs in one place.

## 7. Sentence Style

Preferred sentence style:

- short to medium length
- direct construction
- active voice
- one idea at a time
- low metaphor usage
- low adjective count
- high clarity

Good:
- Import a repo and review detected files before packaging.
- Resume your last draft and continue testing.
- Fix missing fields to complete validation.

Weak:
- Seamlessly unlock the power of your intelligent workflows.
- Effortlessly transform your ideas into next-generation capabilities.

## 8. Vocabulary Direction

Preferred vocabulary:

- build
- test
- validate
- package
- import
- export
- resume
- inspect
- review
- structure
- draft
- handoff
- compatibility
- required
- optional
- complete
- missing
- ready

Use words that reflect action and structure.

## 9. Vocabulary to Avoid

Avoid inflated or generic AI language such as:

- revolutionary
- magical
- genius
- cutting-edge
- next-generation
- game-changing
- supercharged
- powerful in isolation
- unleash
- unlock
- transform everything
- agentic magic

Also avoid soft filler language such as:

- just
- simply
- basically
- kind of
- maybe
- pretty much

## 10. Instruction Style

Instructions should be framed as clear next steps.

Preferred:
- Add a repo URL to begin scanning.
- Review the detected file groups.
- Select the sections to include in the skill package.
- Run validation before export.

Avoid:
- You might want to try adding a repo URL.
- Maybe review your files before you continue.

## 11. Error and Warning Tone

Errors and warnings should feel calm, not punitive.

Preferred pattern:
- state what happened
- state what is missing or blocked
- state what to do next

Example:
- Validation could not complete.
- The skill is missing required instructions.
- Add the missing section, then run validation again.

Do not dramatize errors.

Do not use blame language.

## 12. Success Tone

Success states should be controlled and clear.

Good:
- Skill exported successfully.
- Validation passed.
- Scan complete.
- Draft saved locally.

Avoid:
- You crushed it.
- Amazing work.
- Your skill is now unstoppable.

## 13. Microcopy Rules

Microcopy should:

- reduce uncertainty
- clarify consequences
- reinforce continuity
- help users recover quickly
- stay short unless detail is necessary

Examples:
- Autosaved locally
- Resume available
- 3 required fields missing
- Last tested 12 minutes ago

## 14. CTA Rules

CTA labels should be verb-first and unambiguous.

Preferred:
- Create Skill
- Start Scan
- Review Files
- Run Validation
- Export Package
- Resume Session

Avoid:
- Let’s Go
- Continue Magic
- Make It Happen
- Launch Genius Mode

## 15. Formatting Rules

Use formatting to support clarity.

- keep headings direct
- avoid stacked slogans
- avoid punctuation overload
- use sentence case or title case consistently
- reserve bold for hierarchy, not decoration

## 16. Brand Narrative Rule

Skillaude should be framed as:

- a workspace
- a builder environment
- a structured tool for AI skills
- a place to create, test, inspect, and package reusable capability

Do not frame Skillaude as:

- a chatbot replacement
- a personality-led AI companion
- an all-knowing assistant
- a hype-first AI movement

## 17. Comparison Rule

When referencing Claude, ChatGPT, or other platforms, use neutral and factual phrasing.

Preferred:
- Build skills for Claude, ChatGPT, and other agent platforms.
- Import and package structured skills for multiple environments.

Avoid phrasing that implies endorsement, ownership, or official partnership unless such a relationship exists.

## 18. Default Brand Voice Formula

If a writer is unsure how Skillaude should sound, use this formula:

**Clear first. Structured second. Helpful always. Impressive only through precision.**

## 19. One-Line Rule

When in doubt, write like this:

**Say exactly what the user needs to know, what they should do next, and why it matters. Then stop.**
