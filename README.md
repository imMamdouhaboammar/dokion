## 💡 What is Playbooks Engineering?

Whether you are a **Vibe Coder** or a **Senior Software Engineer**, you rely on AI coding agents every day. But relying on ad-hoc prompts causes agents to hallucinate, skip checks, and generate brittle boilerplate.

> **Playbooks Engineering** is the discipline of turning human-tested, battle-proven software engineering methodologies into **binding, executable constitutions** for AI agents.

A **Dokion Playbook** is not an advice document or a passive prompt suggestion. It is a strict, sequential, and immutable execution workflow that an AI coding agent is **forced to execute line-by-line** without shortcutting, reordering, or hallucinating results.

```text
 ┌────────────────────────────────────────────────────────────────────────────────────────┐

 └────────────────────────────────────────────────────────────────────────────────────────┘

    │ SHA-256 Digest Lock  │ ────►  │ Forced Agent Actions │  ────►  │ Snapshot Comparison  │
    │ Binding Constitution │        │ Tool & Skill Chains  │         │ Zero Regression Gate │
    └──────────────────────┘        └──────────────────────┘         └──────────────────────┘
```

## 🧰 Multi-Skill & Multi-Tool Dynamic Orchestration

A Dokion Playbook does not lock an agent into a single static prompt or fixed toolset. It acts as a **dynamic orchestrator**:

* **On-the-Fly Skill Provisioning**: Playbooks can instruct agents to dynamically install required skills using standard package managers (e.g., `npx skills add <owner/repo>`), follow the skill's procedure step-by-step, and transition to the next phase.
* **Heterogeneous Tool Chaining**: Seamlessly chain static analyzers, unit test runners, git hooks, security scanners, and subagents into a single deterministic pipeline.
* **Codified Methodologies**: Convert a complex manual workflow you have executed hundreds of times into a zero-drift, 100% reproducible Playbook.

Dokion features a native **Playbook Creator** that bridges agent memory with executable code:

```
  ┌────────────────────────┐      ┌────────────────────────┐      ┌────────────────────────┐
  │  Persistent Memory     │      │   Pattern Synthesis    │      │  Executable Playbook   │
  │  (Agent Kernel / Mem0) │ ──►  │   AI Trajectory Analysis│ ──►  │  .dokion/playbook.json │
  │  Interaction Logs      │      │   Successful Repairs   │      │  SHA-256 Locked        │
  └────────────────────────┘      └────────────────────────┘      └────────────────────────┘
```

1. **Memory Extraction**: Inspects persistent memory stores (such as **Agent Kernel**, **Mem0**, or historical agent interaction trajectories).
2. **Pattern Synthesis**: Automatically detects recurring developer corrections, winning repair patterns, and successful bug fixes.
3. **Playbook Generation**: Codifies these synthesized insights into a fresh, validated `.dokion/playbook.json` ready for automated execution.

## 🔒 Authority & Execution Model

Dokion does **not** decide autonomously which capability runs.

* `dokion.json` is an **inert catalog**. It lists available skills, tools, plugins, and policies. Listing an entry does not execute it.
* `.dokion/playbook.json` is the **sole execution authority**. The human developer retains total ownership over:
  * Capability selection & execution order
  * Permissions & approval policies
  * Retry, timeout, and stop rules
  * Verification commands & release gates

Dokion validates, executes, journals evidence, and verifies repairs. It **never** autonomously selects, installs, substitutes, or reorders steps without user consent.

## 🌐 Cross-Agent Architecture

Write your workflow once in canonical representations and run it seamlessly across any AI coding agent:

```text
Canonical Playbook & Skill Representation
  └── skills/dokion-hardening/SKILL.md

Thin Agent Adapters
  ├── Claude Code      ───► .claude-plugin/plugin.json & scripts/claude-playbook-guard.ts
  ├── Codex            ───► AGENTS.md & .codex/AGENTS.md
  ├── Gemini CLI       ───► gemini-extension.json & commands/dokion/run.toml
  ├── Cursor           ───► .cursor/rules/
  └── Antigravity      ───► .gemini/config/skills/
```

Adapters translate discovery, commands, context, and hooks. They **never** alter the underlying playbook logic or grant unearned authority to the agent.

## 🛡️ Snapshot Repair Validation & Exact Rollback

When an AI agent executes a repair step, Dokion enforces rigorous snapshot validation:

1. **Pre-Repair Snapshot**: A complete git tree snapshot is captured immediately before the repair command runs.
2. **Adversarial Inspection**: Post-repair diffs are checked for out-of-scope edits, newly added suppressions (`// @ts-ignore`), deleted unit tests, or skipped assertions.
3. **Exact Rollback**: If remediation, adversarial validation, or verification fails, Dokion **instantly restores the exact pre-repair state**, removing junk files created by the rejected repair while preserving unrelated dirty work.

## 💻 CLI Command Reference

```text
Observe & Audit
  dokion inspect                      Inspect project structure & catalog
  dokion doctor                       Run system & environment health check
  dokion status                       View current playbook execution status
  dokion findings                     List normalized findings & severity
  dokion report                       Generate HARDENING.md summary report

Configure & Plan
  dokion init                         Initialize .dokion state directory
  dokion plan                         Preview exact read-only execution plan
  dokion validate                     Validate playbook schema & digests

Execute & Govern
  dokion run                          Run approved playbook
  dokion resume                       Resume paused playbook run
  dokion verify                       Re-verify findings against gates
  dokion approve <id> --by <user>     Approve step or finding
  dokion reject <id> --by <user>      Reject step or finding
```

## 🚀 Quick Start Guide

### 1. Installation

Global installation via **Bun**:

```bash
bun add --global dokion
```

Or repository-local dev dependency:

```bash
bun add --dev dokion
```

### 2. Minimal Project Workflow

Initialize Dokion state in your project:

```bash
dokion init
```

Create or copy a playbook to `.dokion/playbook.json`:

```bash
dokion validate
```

Preview the read-only execution plan:

```bash
dokion plan
```

Execute the binding playbook with your AI agent:

```bash
dokion run
```
