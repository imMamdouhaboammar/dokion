Current product boundary

Registry rebuild status

The previous public Playbook storefront has been removed because its catalog, metrics, publisher labels, pull flow, and publishing flow were not backed by a complete Registry protocol.

Registry search, package retrieval, installation, publishing, and the Store remain unavailable until Dokion can verify immutable package bytes, preserve provenance, write an auditable lockfile, and keep installation separate from activation.

Implemented boundaries

What the runtime currently protects

User authority

The active .dokion/playbook.json remains the sole execution authority. Discovery and recommendations cannot activate themselves.

Evidence-based execution

Steps must execute through the production engine and produce evidence. Missing execution or verification stops the run.

Controlled repository changes

Worktree policy, scoped permissions, approvals, state integrity, verification gates, and rollback constrain write-capable work.

The Store will sit above a real protocol

  1. Discover validated metadata from explicitly configured, independent Registry sources.
  2. Inspect exact versions, files, capabilities, permissions, compatibility, and provenance before retrieval.
  3. Pull immutable package bytes into a content-addressed cache only after integrity checks pass.
  4. Install a pinned, inert project package and write an auditable lockfile.
  5. Activate only after explicit user intent and the existing Dokion approval rules.

The public website will read a validated static snapshot. It will not be the source of package authority.
